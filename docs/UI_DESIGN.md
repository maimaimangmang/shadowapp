# 多应用扩展的界面约定

更新日期：2026-10-28。

产品未来可能支持其他软件的多开。界面采用“应用 → 该应用的账号空间”两级结构，当前展示 Codex 和 Claude（预览）。

## 导航与内容

- 左侧应用栏只显示软件入口；接入第二个软件后，在同一层级增加入口。
- 右侧顶部显示所选软件、账号空间标题和添加入口。下方是已有窗口与独立空间两组紧凑列表；分组标题附数量，空列表仅显示一句提示。应用在后台自动检测，正常时不显示版本与安装路径卡片；仅检测异常时显示原因、重试和手动选择入口。
- 新建、重命名、打开、切换窗口、正常退出和数据管理属于通用空间操作。按钮中需要出现软件名时，从应用的展示信息取值。
- 应用兼容性和路径选择属于所选应用；空间状态、失败原因和恢复操作显示在对应范围内。
- 菜单栏沿用应用分组，空间归属应清楚；出现操作错误时显示警示图标，并提供查看原因的入口。
- 未支持的软件不显示为可用入口。当前的“选择应用”用于定位所选软件的安装副本。

## 已打开实例与独立空间

- 「已打开的 Codex」只展示尚未归属到当前启动器空间的运行实例，提供切换窗口入口。不会据此推断是个人或工作账号，也不会导入登录信息。
- 独立空间使用自己的目录，首次打开需要单独登录。通过「独立空间」分组与已有窗口区分，避免名称与已有登录身份混淆。
- 全新安装的空间列表为空，不再自动生成「个人账号／工作账号」。已有空间原样保留，不自动删除或重命名旧示例。
- 现有实例的切换不依赖独立空间兼容性检测。列表定时更新，点击时再次验证进程身份。

## 当前实现边界

`ApplicationNavigation.swift` 保存应用的展示信息并实现应用栏；`Dashboard` 组合空间管理界面；`CodexMultiState` 管理状态和操作，供主窗口、菜单栏和自动化检查共同使用；`CodexMultiCore` 继续负责实际的 Codex 隔离和进程验证。

当前支持 Codex 与 Claude；应用展示信息由 ManagedApplication 提供。展示信息不代表启动能力；增加一个枚举值并不能完成软件接入。产品名称为 ShadowApp；图标采用白色 S 与紫色错位投影，应用图标、侧栏和菜单栏共用图形源。

原有 Codex 注册表和目录保持原位；Claude 使用 apps/claude 下的 schema 3 独立注册表，明确记录应用归属。现有 Codex 用户无需迁移数据。

## 接入第二个软件时

1. 先确认该软件的独立实例、登录存储和退出行为，再实现独立的应用适配器。
2. 适配器提供检测、启动、实例识别、正常退出和能力信息。原有 Codex 检查不可直接套用到其他软件。
3. 为注册表增加明确的应用归属，并设计旧数据迁移。旧空间必须确定归属 Codex，保持现有磁盘路径；升级前后的读取和回退行为需要单独验证。
4. 主界面按应用筛选空间，统计只计算所选应用，菜单栏按应用分组。应用切换后不得沿用上一应用的安装路径或实例状态。
5. 根据实际能力显示操作。如果软件不支持某种隔离或管理方式，应说明可用范围，不以通用按钮暗示支持。

空间的“运行中”始终只表示已识别的进程在运行。未验证登录状态时，界面不显示“已登录”，也不从账号文件中抓取身份信息。

## 当前验收要点

- Codex 入口清楚，中文和英文均能显示；正常窗口尺寸下主要按钮不截断。
- 已有空间继续使用原来的数据目录。
- 账号列表异常时显示持续可见的原因和重试按钮，相关数据操作禁用，恢复后无需重启。
- 未安装、版本不支持和启动失败有各自的说明；关闭主窗口后，菜单栏仍有错误反馈。
- 真实账号登录与退出隔离仍按 `COMPATIBILITY.md` 的人工清单验收。

## 简洁布局

主标题只显示当前应用名，右侧保留唯一的新建入口。窗口和空间使用统一行高、图标和右侧操作；重命名、退出与数据管理收进更多菜单。移除页面副标题、重复登录说明、左侧步骤、底部运行摘要和大块居中空状态。首次登录提示放在新建弹窗中。默认窗口为 900 × 560，内容溢出时列表滚动。

## 模型供应商入口

新建弹窗默认选择左侧「API Key」，右侧为「ChatGPT 账号」，仅 API 模式展开供应商、接口地址、密钥和模型 ID。胜算云预填地址，自定义供应商手动填写。列表第二行简短显示供应商与模型，详细编辑放在「… → 模型与 API Key」，运行时禁用。Key 始终使用密码框且不回填已存密钥。名称重复时即时提示，错误固定显示在保存按钮上方，不随表单滚动。模型字段后提供「测试连接」，仅用户点击时发送固定简短请求；支持取消，修改字段会清除旧结果。编辑时测试需要重新填写 Key。保存不自动测试，测试成功仅表示基础 Responses 请求完成。表单底部的兼容性与 Work 登录说明默认折叠在「使用说明」中。

API 空间的表单说明、启动提示及行内 ⓘ 说明引导用户选择 Codex 模式，并解释 Work 浏览器的账号验证要求。使用说明按需展开，不新增常驻大段说明。

## 2026-10-29：中性配色调整

侧栏使用浅灰底、白色选中项和细分隔线，主区域为近白底与白色卡片。主要操作使用深灰按钮，链接使用系统蓝色；深色模式反转主要按钮并使用分层灰色背景。账号图标降低饱和度，绿色只保留为运行状态指示。卡片内边距统一 16pt、圆角 12pt，侧栏宽 184pt。API 表单增高以容纳注册提示和统一按钮。

新建空间的 ChatGPT 账号模式、重命名弹窗按内容自动确定高度；API 模式使用有界滚动区域，避免固定小高度裁切说明。已打开实例的操作统一使用「显示窗口」。

空间卡片下方显示 `…/profiles/空间目录名`，省略冗长父目录；悬停显示完整路径，文件夹图标打开目录，复制按钮复制绝对路径。已有目录不因命名规则升级而移动。

固定数据根目录为 `~/CodexMulti`；空间卡片用 `~` 简写用户主目录并保留根目录名称，完整绝对路径可悬停查看和复制。

## 2026-10-29：Claude 接入

侧栏和菜单栏增加 Claude，使用安装包图标，记住最近选择的应用。每个应用有自己的空间列表、状态和错误提示；同名空间可分别存在于不同应用。Claude 新建表单同样默认选择左侧 API Key，右侧 Claude 账号；按应用提供不同的网关地址、接口协议、模型校验与使用说明。限制说明默认折叠。Codex 保留 API Key 默认选项。原有空间路径不变，Claude 卡片显示其实际 apps/claude 路径。

WorkBuddy 使用统一的「新建空间」、空间列表与已有窗口操作。创建时仅填写名称，提示独立主目录与逐个登录；暂不展示启动器 API Key 表单，模型配置指向 WorkBuddy 原生设置。多开标为预览并说明更新后的重新启动要求。
